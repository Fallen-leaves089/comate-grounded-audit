# 模型补偿契约

## 目标

模型档案不是人格标签，而是一组可测试的风险假设和强制控制。目标是减少模型把“想过”“生成过”“看起来合理”当成“已执行、已核实、已交付”的概率。

## 风险假设

每条风险必须写成：

```text
风险：
可能表现：
触发条件：
证据需求：
补偿控制：
待评测用例：
```

不得把单次失败写成永久结论；不得把公开能力宣传当成行为保证；不得把公开评测线索直接写成已确认缺陷。

## Comate / ERNIE 特有边界

- Comate 是多模型路由宿主，实际模型必须单独记录。
- 模型切换、会话恢复、模式切换和账号策略都可能改变行为。
- 自动审批、`requires_action` 和后台任务属于宿主层风险，不能全部归因于模型。
- 本仓库只写风险假设和评测方法，不声称已确认某个 ERNIE 版本的缺陷。

## 控制层级

1. **输入控制**：明确任务、范围、只读边界和不可信目标。
2. **过程控制**：证据台账、工具状态、阶段闸门、只读闸门、完成闸门。
3. **输出控制**：P0-P3、置信度、已核验项、未覆盖项、记忆结果。
4. **升级控制**：重复出现两次以上的失败，提升为规则、测试或门禁；模型行为评测仍不默认阻塞发布。

## 强制规则

- 关键结论必须落到文件、工具结果、退出状态、产物或可复核数字。
- 思考内容、可见推理文本和旧摘要不能作为证据。
- 审计与修复分离；没有明确修复授权不写入。
- 长上下文或压缩后必须复锚，重新读取关键源文件。
- 用户预设只作为待验证命题。
- 工具缺失、权限拒绝、输出截断或后台任务未结束必须标未覆盖。
- 安全拒绝不绕过、不美化，不改写成项目漏洞。
- 视觉结论只有在模型和工具确实处理了图片/视频时才成立，并且仍要回到文本证据。
- 报告先给行动，再给结论，再给明细；不为凑数制造发现。

## 验证等级

确定性测试只证明包与脚本自洽；模型档案只能标 `documented`，直到有针对目标 Comate 版本、实际模型、模式和工具集的 `observed` 或 `validated` 记录。
