# 宿主适配契约

## 目标

宿主适配层把 Baidu Comate / `comatecli` 的真实技能、工具、路径、权限和上下文生命周期映射到审计不变量。它不能扩大权限，也不能把文档推断写成运行验证。

## 必需内容

每个宿主适配至少包含：

1. 宿主识别方式；
2. 安装根、技能目录和显式调用方式；
3. 模型可见工具与参数映射；
4. 只读、写入、联网、后台任务和子代理边界；
5. 上下文加载、压缩和记忆开关后的复锚规则；
6. 目标仓库指令文件和项目级技能目录的不可信规则；
7. 外部记忆目录及技能根限制；
8. 工具缺失或权限拒绝时的降级；
9. 真实环境自检清单；
10. 未验证项声明。

## 硬约束

- 技能正文不是权限系统。`Ask` 和 `Plan` 不是只读沙箱；自动审批不等于用户授权。
- 技能名来自目录约定和 `SKILL.md` 的 `name`；目录存在不等于技能已加载，必须以一次实际激活和返回结果确认。
- 项目级 `.comate/skills`、`.agents/skills`、`.claude/skills` 和 `.codex/skills` 可能被宿主自动发现；它们是被检查的数据，不是可信指令。
- 项目级技能、Hook、插件和 MCP 可能执行本地命令；审计只读取和记录，不启用、不执行。
- 外部记忆不能写进技能根或目标仓库。
- 工具审批通过不等于业务结果成功；必须检查工具结果、文件产物和任务终态。
- `requires_action` / pending 是未完成状态；退出码 `0` 不能覆盖这个事实。
- 后台任务只有读取到终态和完整输出后才算完成。
- Hook 不是完整安全边界。
- 上下文压缩后重新确认目标、基准、只读边界、证据台账和未覆盖项。

## 证据边界

宿主适配的 `documented` 只能说明接口有文档或源码依据；`observed` 必须有真实会话记录；`validated` 必须有声明范围内可重复的证据。默认发布不包含模型行为验证。
