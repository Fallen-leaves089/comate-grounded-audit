# 验证与完成判定

## 1. 证据账本

开始执行命令前先建立账本，至少记录：

```text
检查项 | 命令/工具 | cwd | 退出码 | 关键输出 | 产物 | 状态 | 未覆盖原因
```

状态只用：`verified`、`observed`、`inferred`、`not-covered`。`verified` 必须有可复跑证据；`observed` 只说明本次看到；`inferred` 必须标明推断；`not-covered` 不能写成通过。

## 2. Comate 的完成契约

- 记录 Comate 版本、运行模式、实际模型、权限状态和激活的技能。
- `run_command` 可能产生长输出、挂起或后台任务；记录 cwd、退出码、stderr、信号和超时。
- `requires_action` 默认可能以退出码 0 结束；显式设置 `--requires-action-exit-code 2`，并检查 `comatecli pending`。
- `--background-timeout` 不设置时可能无限等待；后台任务必须设置边界并读到终态。
- 启动不等于完成；输出预览不等于完整日志。

## 3. 完成判定

一个检查项只有在以下条件同时满足时才算完成：

- 命令或工具确实执行；
- 退出码为 0，或失败被明确记录；
- 没有未处理的 `requires_action` / pending；
- 关键输出已读取，没有只依赖截断预览；
- 后台任务已到终态；
- 业务产物存在且可复核；
- cwd、环境变量、模型和前置条件与结论匹配。

只有退出码 0 才是成功，但退出码 0 不等于完成。后台任务必须读到终态和完整日志。切换会话、关闭界面或改变模式对后台工作的影响不同，不能假定离开界面等于停止任务。

## 4. 假绿清单

以下都不能单独证明成功：

- 日志里出现 `PASS`、`OK`、`success` 或“通过”；
- 测试数量大于 0；
- 配置文件存在；
- 命令已启动或进入后台；
- `requires_action` 以退出码 0 结束；
- 产物文件存在但未校验内容；
- 模型自己说“已检查”；
- 子代理返回“无问题”；
- CI 缓存命中；
- 旧报告或旧构建结果。

## 5. 上下文压缩与模型切换

Comate 可能压缩、截断或重排上下文；本适配不依赖固定阈值。压缩、切换模型/模式或恢复会话后必须：

- 重读关键源文件和配置；
- 重查后台任务、pending、模式、实际模型和目标路径；
- 核对证据账本；
- 不直接把压缩前或切换前的“已通过”复制到当前结果。

## 6. 权限拒绝与安全拒绝

权限拒绝、安全拒绝、超时、输出不可读、工具缺失、存在 pending 和后台任务未结束都属于未覆盖或未完成。不能改写成“没有发现问题”，也不能用推断补足。
